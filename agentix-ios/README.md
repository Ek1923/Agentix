# agentix-ios

The iOS build. A Capacitor shell around the web app, ready to open on a Mac.

**Everything here is scaffolded and nothing has been compiled.** Xcode only runs on
macOS, so this is complete up to the point where a Mac is required.

## Why this exists alongside the planned Swift build

The brief locks iOS to a Swift rewrite, and that is still the right destination.
This is the route to TestFlight in the meantime: a rewrite is weeks of work to
learn what a day of real testers would tell you. Shipping the app that exists
first means the Swift build later answers a question rather than guessing at one.

Nothing is wasted either way. The files the Swift build will translate — `core/`
and every plugin's `logic/` — are untouched by this.

## Layout

```
agentix-ios/
├── capacitor.config.ts   appId, appName, webDir → ../agentix-web/dist
├── package.json          build and sync scripts
└── ios/App/              the Xcode project, generated by `cap add ios`
```

Capacitor 8 uses Swift Package Manager rather than CocoaPods, which is why the
project could be generated on Windows at all.

## Getting to TestFlight

**Before you touch a Mac:** enrol in the Apple Developer Program ($99/year). It is
the only step with a wait you cannot shorten — allow a couple of days.

On the Mac, with Xcode installed:

```bash
npm install
npm run sync     # rebuilds the web app and copies it into ios/
npm run open     # opens ios/App/App.xcworkspace in Xcode
```

Then in Xcode:

1. Select the **App** target → Signing & Capabilities → tick *Automatically manage
   signing* and pick your team. Let Xcode create the certificates; doing this by
   hand is the historically painful part.
2. Set the version and build number.
3. Product → Archive, then Distribute App → App Store Connect → Upload.
4. Wait ten to thirty minutes for processing.
5. In App Store Connect → TestFlight, add **internal testers** — up to 100 people
   with access to your account, and **no review required**. That is how you test
   it yourself, today.
6. **External testers** (up to 10,000) need Beta App Review first. Usually a day.

## Four things that will bite at review

**Sign in with Apple.** Required. The gate offers Google and GitHub as well as
email and password, and *either* of those two makes Apple mandatory — the rule is
about third-party login in general, not about Google. The buttons all ship, so the
only thing missing is the Apple side of the Supabase configuration, which needs the
$99/year membership. Enable it before you submit, or the build gets rejected.

**Privacy labels.** Agentix collects nothing, which is a rare and easy answer. The
nuance to be ready to explain: a note's text and the user's own API key go to
Anthropic or OpenAI when *they* press Summarise. That is user-initiated and never
touches a server of yours. `PRIVACY.md` at the repo root is the document that says
so; it needs to live at a public URL.

**Export compliance.** One checkbox. The app uses HTTPS only, so the standard
exemption applies.

**"Where is the functionality?"** Apps that look empty without configuration get
rejected. Agentix degrades deliberately without an API key — put in the review
notes that tasks, the board, the timer, habits and every statistic work with no
key at all, and that only the note summary needs one.

## What the port needed

**Real haptics.** WKWebView does not implement the Vibration API, so `feedback.ts`
was silent on iOS. It now detects a native platform and routes through
`@capacitor/haptics`, whose calls land on exactly the generators the event names
were chosen for:

```
selection         → UISelectionFeedbackGenerator
light / medium    → UIImpactFeedbackGenerator(style:)
success / warning → UINotificationFeedbackGenerator(type:)
```

The plugin is loaded by dynamic import behind a native check, so a web visitor
never downloads a native bridge to be told there isn't one.

**A dark WebView background.** The WebView paints before the app's CSS arrives;
left at the default, every cold start flashed white before the dark theme landed.

**No text rescaling on rotation.** WKWebView resizes text when a device rotates
unless told not to, which reflows the board mid-drag.

## Not yet done

Everything past `npm run open`. Nothing has been built, signed, uploaded or run on
a device or simulator.

Worth checking first, because only a device shows them:

- haptics actually firing, and feeling right rather than constant
- safe areas around the notch and the home indicator
- the board's horizontal scroll and card drag under touch
- IndexedDB surviving the app being backgrounded and evicted
- a cold start showing dark, never a white flash
