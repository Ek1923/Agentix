# agentix-android

The Android build. A Capacitor shell around the web app — not a second codebase.

## Why Capacitor and not React Native

The brief says Android is **ported from web**, and Capacitor is the only reading
under which that is literally true. The same TSX runs unchanged: the same Dexie
over IndexedDB, the same Tailwind, the same Framer Motion, the same plugin host.

React Native would mean rewriting all forty components against a different
rendering model, replacing Dexie with SQLite, and replacing Tailwind with
StyleSheet — a rewrite. A rewrite is exactly what the iOS Swift build already is,
and two rewrites for three platforms is one too many.

The consequence worth knowing: **a fix to `agentix-web` is a fix to Android.**
There is no second implementation to keep in step.

## Layout

```
agentix-android/
├── capacitor.config.ts     appId, appName, and webDir → ../agentix-web/dist
├── package.json            the build and sync scripts
└── android/                the native project, generated by `cap add android`
```

`webDir` points at the web build rather than a copy. There is one source of truth,
and `npm run sync` rebuilds it before every native sync.

## Building it

**Prerequisites:** a JDK (17 or newer) and the Android SDK. The simplest route is
Android Studio, which installs both and provides the emulator.

```bash
npm install              # once
npm run sync             # rebuilds the web app and copies it into android/
npm run open             # opens the project in Android Studio
```

From Android Studio: pick a device or emulator and press Run. To produce a
release APK or AAB, use Build → Generate Signed Bundle / APK; the signing
keystore is gitignored and must never be committed.

`npm run run` does the sync and launches on a connected device in one step, if the
SDK's `adb` is on your PATH.

## What the port needed, and what it did not

**It needed history-based routing.** A WebView hands the hardware back button to
`history.back()`. With the route in React state there was nothing to go back to,
so Android's back button closed the app from any screen — the most jarring thing a
ported web app can do. `agentix-web/src/shell/router.ts` now keeps the route in the
URL hash, which fixes Android and gives the web build browser back and forward at
the same time. One mechanism, both jobs.

A hash rather than a path, because neither a WebView nor GitHub Pages rewrites
unknown paths to `index.html`.

**It needed safe areas.** `viewport-fit=cover` lets the page paint under the notch
and the gesture bar; the `env(safe-area-inset-*)` padding in `index.css` puts the
content back where a thumb can reach it. Every value is zero on the web, so the
same rules are harmless there.

**It needed pull-to-refresh turned off.** A downward drag at the top of a WebView
reloads the app. There is nothing to refresh — the database is local.

**It did not need a haptics plugin.** `ui/feedback.ts` names interaction moments
semantically and drives them through the Vibration API, which an Android WebView
supports. Android therefore gets haptics through the code that was already there.
iOS is the platform that needs a real implementation, mapping the same event names
onto `UIFeedbackGenerator`.

**It did not need a storage change.** IndexedDB is a first-class WebView API, so
Dexie, the sync outbox and the separate `agentix-secure` key database all behave
exactly as they do in a browser.

## Not yet done

**No APK has been built.** The scaffold is complete and `cap sync` copies the web
build correctly, but this machine has a JDK and no Android SDK, so nothing has been
compiled or run on a device. That is the first real test of the port.

Worth checking specifically on a device, because only a device can show them:

- the hardware back button walking home from a plugin, and closing the app from home
- safe areas on a device with a notch and a gesture bar
- the board's horizontal scroll and card drag under touch rather than a mouse
- IndexedDB surviving the app being backgrounded and killed

**API keys.** The device-only warning in Settings still says "this browser's
IndexedDB". On Android that is the app's own WebView storage, which is sandboxed
per app and rather better than a shared browser profile. The wording should say so
once the port is real.
